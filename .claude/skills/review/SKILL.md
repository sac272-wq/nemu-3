# review — 投稿後ふり返り

## やること
投稿の数字を見て、何が効いて何がダメだったかを整理し、次にやることを決める。

## 使わんとき
- コードレビュー
- アフィ以外の投稿

## 手順
1. 共通メモを読む
2. 数字を集める
   - Threads側（閲覧・いいね・リプ・リポスト・フォロワー）：スレハックMCPが使えるなら
     `get_my_mcp_access` で確認してから取る。使えなければユーザーに貼ってもらう
   - ASP側（クリック数・成果）：ASPの管理画面にしかないので、ユーザーに貼ってもらう
   - 無い数字は「なし」と書く。推測で埋めない
3. 投稿ごとに表にする（投稿日時、冒頭、リンクの置き場所、各数字）
4. 比べる：反応が良い投稿と悪い投稿で、冒頭・構成・時間帯・リンクの置き場所の違いを見る
5. 次にやることを1〜3個決める（例：「冒頭を悩み型に変える」）
6. 共通メモの「review：ふり返り」に日付つきで書く。次に case / hook / post のどれに戻るかも書く

## 守ること
- 判断に何本の投稿が必要かは、ユーザーに決めてもらう。足りなければ「まだ判断できない」と言う
- 原因は「〜かもしれない」で書く。わからないものはわからないと書く
