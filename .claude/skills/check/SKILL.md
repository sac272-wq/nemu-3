# check — 投稿前チェック

## やること
本文を見て、出したらマズい所がないか確認し、直し案を出す。

## 使わんとき
- コードや文書のチェック・レビュー
- アフィ以外の投稿

## 手順
1. 共通メモと本文を読む（商品ジャンル、ASP名、実体験、ASP規約で確認済みのこと）
2. 次の項目を1つずつ ○／×／要確認 で判定する
   - PR表記がある：広告だとわかる書き方か
   - PR表記の位置：冒頭か目立つ所にあるか。ハッシュタグにまぎれていないか
   - 体験が本当か：共通メモの実体験と合っているか
   - 薬機法：化粧品・健康食品・サプリで「治る」「痩せる」など効果・効能をうたっていないか
   - 景表法（優良誤認）：「絶対」「No.1」など、実際よりすごく見せる表現に根拠があるか
   - 景表法（有利誤認）：「最安」「今だけ」など、実際よりお得に見せる表現に根拠があるか
   - 価格・期間：古い情報や、確認していない情報がないか
   - ASP規約：SNS掲載・リンクの直貼り・NGワードについて、確認済みか
   - スパムっぽさ：同じリンクや同じ文面を何度も投稿していないか
3. × と 要確認 だけ直し案を出す
4. 最後に「出してOK／直してから出す」をまとめ、共通メモの「check：結果」に日付つきで書く

## 守ること
- ASPや案件ごとの細かい規約は断定しない。確認済みでなければ「要確認」にして、規約を見るよう伝える
- 法律の判断はしない。グレーなものは「要確認」にする
- 投稿はユーザーが自分で出す。勝手に公開・予約しない
